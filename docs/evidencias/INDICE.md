# Índice de evidencias

Registro de las ejecuciones de las suites de pruebas del proyecto. Cada fila corresponde a
una corrida y a un fichero de log en esta carpeta con la **salida cruda** del comando, sin
edición: lo que la consola imprimió, redirigido a fichero con `> fichero 2>&1`. La única
normalización aplicada al publicarlos es sustituir la ruta local del repositorio por `<repo>`;
ningún resultado se alteró.

Convención de nombres: `AAAA-MM-DD_<proyecto>_<suite>.log`.

## Cómo reproducir

```bash
# zk-circuits: recompila el circuito antes de probar
cd zk-circuits && npm test

# zk-contracts: sólo la frontera del verificador y la sustitución de esquema
cd zk-contracts && npx hardhat test test/verifier-boundary.test.ts

# zk-contracts: suite completa, incluida la integración
cd zk-contracts && npx hardhat test

# zk-contracts: sólo la integración con T-REX
cd zk-contracts && npx hardhat test test/integration-erc3643.test.ts

# zk-api: exige PostgreSQL y Redis levantados (docker-compose up -d)
cd zk-api && npm test
```

La integración lee el circuito compilado de `zk-circuits/build/`. Si esa carpeta no existe,
hay que construirla antes con `npm run build` en `zk-circuits` y `./scripts/setup.sh` para
las claves. `./scripts/setup.sh` genera las claves de **los dos** esquemas, y las fixtures de
`zk-contracts` se regeneran con `node test/fixtures/generate-proofs.mjs`, que prueba cada
escenario bajo Groth16 y bajo PLONK.
